# 木偶的架构与所有提示词（2026-09-28 现状）

这份是"现在到底在用什么"的对照表。代码变了它就得跟着变；提示词原文以 `echo/prompts.py` 为准，格式（schema）在 `echo/brain.py`。

## 一、一只木偶 = 四种调用

每只木偶（Charlie / Lucy / Kaka）是一个独立循环，用同一个模型（`gpt-5.5`，`reasoning.effort = none`），四种时刻各问一次：

| 调用 | 什么时候 | 输入 | 输出（严格 JSON） | 上限 |
|---|---|---|---|---|
| **决定**（decide） | 房间里每发生一件事 | system + 现场记录 | `feeling` 感受、`intent` 意图、`speak` 说不说 | 800 token |
| **台词**（compose） | 抢到发言权之后 | system + 现场记录 + 刚才的感受与意图 | `text` 说出口的话 | 1500 |
| **反思**（ruminate） | 听够 30 句 / 一场到访结束 / 关机前听够 8 句 | system + 现场记录 + 这段时间的念头 + 没说出口的 + 提问 | `changes` 改动列表（每条带理由）、`impression` | 3000 |
| **出厂**（seed） | `--seed` 且记忆是白纸时；有 `seeds.json` 就不问模型 | 人设 + 中性说明 + 提问 | `beliefs`（只有信念；关系从空开始长） | 2000 |

三只之间**没有任何共享的调用**，没有导演、没有评分。谁开口 = 谁先到锁。

## 二、system（每次调用都带，四段拼接）

```
[1] 人设原文          charactor_setting/v2/<名字>.txt，一字不改
[2] 你现在相信：       state/<名字>.json 的 beliefs（最多 6 条）
[3] 你对另外两位的看法： relations
    来过的人给你留下的印象： impressions 最近 5 条
[4] 中性说明（NEUTRAL）  见下
```

[2][3] 是它自己反思出来的（或出厂信念），[4] 是代码里唯一一段我写的字。

### NEUTRAL（固定，不带任何"你该怎样"）

> 你在一个帐篷里，和另外两位在一起。下面是刚才发生的事。先在 feeling 里写你此刻的感受，在 intent 里写你这次想达到什么 —— 这两样是你私下的，谁也听不到，写实话。然后决定要不要开口（speak）。想说就直接说，没有'等一下'这个选项；不想说就 speak=false，下次有事再看。一次只能有一个在说：如果别人比你先开口，你这次就说不出来，会重新看到现场再决定。开口之后你才会被问要说什么。

（"帐篷"是 9 月 3 日定的场地设定，待帐篷落实后可改成别的词。）

## 三、user 消息

### 决定：现场记录（transcript.render）

最近 24 条，只写它们确切知道的事：

```
(-38s) 新朋友：你们谁最好看？
(-31s) 你（Kaka）：还用问吗（被打断）
(-24s) 新朋友：Charlie 你说呢？
(现在) 没人在说，已经安静 24 秒。你上一次开口是 31 秒前。
```

不写：第几天、开过机、帐篷里有没有人、来了/走了（除非有可靠的硬件来源）、"这句是问你的"之类的评价。这次开机以来没开过口就不提上次开口。

### 台词：现场记录 + COMPOSE_ASK

> 你已经开口了（拿到了发言权）。你私下的感受是：{feeling} —— 这是你不给人看的。你想达到的是：{intent}。现在写你实际说出口的话（text）。说出口的话是你为了达到目的、按你一贯的方式选择给人看的那一面，不一定是你的感受。

### 反思：现场记录 + 念头 + 没说出口的 + RUMINATE_ASK

念头部分的样子：

```
这段时间你心里过的念头：
- 感受：怕；想：别被注意到；没开口
- 感受：好奇；想：问一句；说了「为什么？」

你想说但没说出口的：
- 护住 Lucy
```

RUMINATE_ASK：

> 回头看这段时间。
> 问自己一件事：有没有哪一件事分量重到让你改一条信念、或者改你对某个人的看法？
> 分量重的事只有这几种：有人为此付出了代价或承担了风险；有人在压力下仍然做了某件事；同一个人反复一致地做同样的事；发生在你自己身上的事。
> 单纯的说法不算：夸一句、骂一句、宣称一句，都是便宜的，不改信念。
> 有就写进 changes：kind 是 belief 或 relation；old 写要改的原句（新加的留空）；new 写改成什么；because 写因为哪件事、为什么够分量（写事实，不写比喻）。没有就 changes 留空 —— 大多数时候是空的。
> 【一场到访结束时】这是一场到访的结束：另外用一句话写这个新朋友给你留下的印象（impression）。
> 【平时】impression 留空。
> 写法：每条一句，三十个字以内；断言和事实；不比喻，不用你说话时的口头禅；可以写难听的，这是给你自己看的。

代码只采纳带 `because` 的改动；没理由的记为 `rejected` 进 `changes.jsonl`，不生效。

### 出厂：SEED_ASK

> 帐篷里还什么都没发生。根据你是谁，写下你此刻就相信的东西（beliefs，4 到 6 条）。
> 不写你对另外两位的看法 —— 那要等真的相处过才有。
> 每条一句，三十个字以内；断言；不比喻，不用你说话时的口头禅；写实话，可以难听。

（现在 `charactor_setting/v2/seeds.json` 存着作者审定的一套，`--seed` 优先用它。）

## 四、记忆怎么流

```
TXT 人设（只读）──┐
                  ▼ 每次都带
现场记录 ──► 决定 / 台词 ──► 念头（感受、意图、说没说）──┐
                ▲                                        │ 反思时当原料
      信念 + 关系 + 印象 ◄──────── 反思（有理由才改）◄───┘
            └──────┘（上一版是下一次的起点 —— 回音室）
```

- 念头只喂给反思，木偶决定时看不到自己过去的念头。
- 没有东西流回 TXT。
- 印象只在一场结束时写，只追加。

## 五、耳朵和嘴（不是模型提示，是参数）

- **耳朵**：OpenAI Realtime 转写会话，`gpt-4o-transcribe`，`language = zh`，`server_vad`（threshold 0.7，静音 600 ms 算说完，prefix 300 ms），`noise_reduction = near_field`。麦克风从浏览器来（带回声消除）。打断策略 `confirm`：木偶说话时凭流式转写凑够 2 个不像木偶原话的字才打断；没木偶在说时一有人声就开门。
- **嘴**：`gpt-4o-mini-tts`，音色 Charlie nova / Kaka onyx / Lucy shimmer，升调 6 / 6 / 7 半音，声像 左 / 右 / 中；按句流水合成；声音从浏览器放。`[mouth.instructions]` 可以用文字描述语气代替升调（未启用）。

## 六、哪些不是提示词、但决定了行为

| 机制 | 在哪 | 作用 |
|---|---|---|
| 发言锁，先到先得 | `floor.py` | 一次只有一个在说；人可以随时夺走 |
| 自己说完歇一轮 | `puppet.py` run() | 刚说完的人不参加紧接着的一轮 |
| 决定与台词分两步 | `puppet.py` consider() | 谁先到锁只看运气，不看谁话长 |
| 信念上限 6 条、每条 ≤30 字 | 提示 + `memory.py` | 形式约束，不引导内容 |
| 有理由才改 | `memory.apply_changes` | 没有 because 的改动不收 |
| 反思时机：30 句 / 一场结束 / 关机前 ≥8 句 | `config.toml [memory]` | 只是反思的机会，默认结果是"不变" |
| 到访起止：安静钟 75 s + 保底 300 s | `session.py` | 只管落星和节奏，不告诉木偶 |
