# 回音室 · 对话引擎设计

日期：2026-09-03（设计）· 2026-09-04（阶段 1 实现，本文档已按实际代码校正）
状态：阶段 1 已实现；阶段 2 起待作者审阅
范围：帐篷里"讲话的那个东西"。不含投影、不含硬件动作的最终形态（但留好接口）。

---

## 0. 一句话

三只木偶各自是一个独立的循环：帐篷里发生了任何事，它们同时收到一份如实的现场记录，各自在角色里决定"现在开口还是不开口"。先开口的拿到一把锁，其余的话咽回去。代码只提供**耳朵、嘴、和这把锁**，不提供动机。

## 0.5 跑起来（阶段 1 已实现）

```
cd echo-chamber-realms
.venv/bin/pytest -q                              # 39 个测试，不调真模型、不花钱、不需要 key
.venv/bin/python -m echo --fake                  # 假脑子（固定台词），看机制：抢锁、咽回去、打断、落盘
.venv/bin/python -m echo                         # 真脑子：按 config.toml 的 provider 读 OPENAI_API_KEY 或 ANTHROPIC_API_KEY
```

终端里：打一行回车 = 说一句；单独一个 `.` = 先开口（打断正在说的那只，之后那一行才是你说的话）；Ctrl-C = 关机（暂停，不是清空；听够 8 句会先"睡前整理"一次）。

启动开关：`--reset Charlie`（或 `all`）把那只的记忆挪到 `state/reset-<时间>/`、从白纸开始，**改了人设就要用**；`--seed` 给白纸的木偶装出厂信念 —— 有 `charactor_setting/<dir>/seeds.json`（作者审定的那份）就用它，没有才从人设生成。改人设的完整动作：改 txt → `--reset 谁 --seed`。运行中**不要手改 `state/*.json`**，引擎只在启动时读一次、之后每次改动都会覆盖写。

**作者监控台**：开机后打开 http://127.0.0.1:8765 —— 左边是流水（谁说了什么、谁开口了、谁咽回去、谁没开口、安静了多久），右边是三只木偶的记忆（相信什么、对另外两位、想说但没说、来过的人留下的），顶栏是第几天 / 帐篷里有没有人 / 谁在说 / 安静多久。底下能打字、能按"打断"。它只是房间的一个订阅者加一个键盘替身，对引擎没有额外权力；观众永远看不到它。端口在 `config.toml` 的 `[monitor]`，设 0 关闭。终端的打字渠道同时保留。

状态全在 `state/`（已 gitignore）：

| 文件 | 内容 |
|---|---|
| `transcript.jsonl` | 原话流水，只追加。木偶不读它，作者读 |
| `charlie.json` / `lucy.json` / `kaka.json` | 每只木偶的记忆：信念、关系、印象、未说出口的话 |
| `changes.jsonl` | 每次反刍前后的差异（删了什么、写了什么）—— 墙二的数据源 |
| `sessions.jsonl` | 每场到访、每只木偶一条印象 —— 墙三的星 |
| `days.json` | 开过机的日历日；第 N 天 = 长度 |

旋钮在 `config.toml`，改了下一轮生效。

代码地图（`echo/`，每个文件一件事）：`room.py` 总线 + 锁的人类优先 + 沉默计时 + 到访起止 → `puppet.py` 木偶循环 → `brain.py` 模型（`ClaudeBrain`）；`transcript.py` 是木偶看到的世界；`memory.py` 是它们记住的东西；`floor.py` 是那把锁；`mouth.py` / `motors.py` 是嘴和动作的关闭模式；`console.py` 是键盘替身；`clock.py` 让测试能操控时间；`__main__.py` 把这些接起来。

一个实现时发现的细节：木偶在**构造时**就订阅房间（不是在循环启动时），否则任务还没轮到跑、开机第一批事件就漏了。

## 1. 原则（读懂整个系统的钥匙）

**1.1 不指挥。** 代码里没有"谁该说""谁性子急""这个话题是谁的"。没有计分、没有冷却时间表、没有谁让谁的规则。三只木偶的一切行为，来源只有 `charactor_setting/` 里作者写的三份人设。如果它们轮流得死板、或者 Kaka 从头说到尾，那是这三个人设在这个房间里的真相 —— 改人设，不改代码。

**1.2 如实。** 木偶收到的现场记录只陈述事实：谁说了什么、现在谁在说、安静了多久、你自己上次开口是什么时候、帐篷里有没有人、昨晚关过机。不加评价，不加暗示。

**1.3 一次只有一个在说。** 木偶或人。这是物理约束（一个帐篷、一组音箱），不是设计偏好。

**1.4 人永远能打断。** 人一开口，正在说的木偶立刻停 —— 音频停、动作停。

**1.5 随时可以拔电。** 所有状态在磁盘上，每次改动立即落盘。夜里关机是暂停，不是清空。

**1.6 沉默是内容。** 三只都决定不说，就是安静。安静本身也是一件会被它们感知、可以被反应的事。

```
                          │                 房间（room）                  │
  麦克风 ──► 耳朵(ears) ──►│  事件总线 · 现场记录(transcript) · 发言锁(floor) │
  键盘  ──► 控制台(console)│                                              │
                          └───┬──────────────┬──────────────┬───────────┘
                              │ 同一份现场记录 │              │
                              ▼              ▼              ▼
                         木偶 Charlie    木偶 Lucy       木偶 Kaka        ← 三个独立循环，各调各的模型
                              │              │              │
                              └──── 想开口 → 抢锁 ──────────┘
                                          │ 抢到的那只
                                          ▼
                              嘴(mouth: TTS→升调→声道→音箱)
```

组件清单（每个一个文件，各管一件事）：

## 3. 房间：事件、现场记录、锁

### 3.1 事件

房间里只会发生这几种事：

| 事件 | 来源 | 含义 |
|---|---|---|
| `human_started` | 耳朵 / 控制台 | 有人开口了（还不知道说什么） |
| `human_said(text)` | 耳朵 / 控制台 | 人说完了一句，文字是 text |
| `puppet_started(name)` | 锁 | 某只木偶拿到锁、开始说 |
| `puppet_said(name, text)` | 嘴 | 某只木偶说完了 |
| `puppet_cut(name, spoken)` | 锁 | 某只木偶被打断，只说出了 spoken 这部分 |
| `quiet(seconds)` | 房间计时器 | 已经安静了这么久（周期性发出） |
| `visitor_arrived` / `visitor_left(session_id)` | session | 一场到访开始 / 结束（结束时带这一场的 id，反刍用它写印象） |
| `woke_up(day)` | 主循环 | 开机了，今天是第几天 |

每个事件都追加进**现场记录**（transcript），这是一份带时间戳的、只增不减的流水。它同时写进 `state/transcript.jsonl`。

### 3.2 发言锁（floor）

- 任何时刻锁至多被一个说话者持有：某只木偶，或者人。
- **人有绝对优先权。** `human_started` 到来时：若某只木偶持锁，立即调用 `mouth.stop()` 和 `motors.stop(name)`，发出 `puppet_cut`，锁转给人。人持锁期间木偶抢锁一律失败。`human_said` 之后锁释放。
- **木偶之间先到先得。** 木偶决定开口 → `floor.try_acquire(name)`：锁空闲则成功；已被占则失败，这句话成为该木偶的**未说出口的话**（见 §5.3）。
- 木偶持锁至嘴播完为止（`puppet_said`），或被打断为止。

**平局怎么定：** 两只几乎同时想开口时，谁的回复先生成完谁先拿到锁。这本质上是掷硬币。作者决定接受它（2026-09-03）：随机不是指挥。

### 3.3 沉默计时

房间在没有任何人说话时，每隔 `quiet_interval` 秒发一次 `quiet(seconds)`，seconds 累计。有人在帐篷里和没人时用两个不同的间隔（`quiet_interval_with_visitor` / `quiet_interval_alone`），后者长得多 —— 这就是"无人时慢速自聊"的全部实现：不是让它们少说，是让"安静"这件事被感知得慢一点。

## 4. 木偶：一个循环

三只木偶是三个并发的、完全对称的循环，唯一区别是各自的人设文件和各自的记忆。

```
loop:
    等一个新事件（任何事件都算）
    如果上一轮的模型调用还没结束 → 取消它，用最新的现场重来
    组装现场记录（§4.1）
    问模型：现在开口，还是不开口？（§4.2）
    不开口 → 什么都不做
    开口   → floor.try_acquire(我)
              成功 → 交给嘴和动作；等说完；释放锁
              失败 → 记为"未说出口"（§5.3）
```

"取消重来"很重要：木偶正在斟酌上一句时又来了一句，它应该对最新的现场做反应，而不是对一个已经过时的房间说话。

**刚说完的人让一轮**（2026-09-25 加）：自己的"说完了"（或"被打断了"）不算新事，不触发再决定。别人开口、人开口、或安静了（`quiet`）才轮到它 —— 这就是会话分析里的第三条规则"没人接，原说话人才可以继续"。之前漏了它，结果 Kaka 说完立刻再报 0 秒又抢到，别人永远插不进：刚说完的人平白多了一次抢先，那是机制不是人设。

### 4.1 木偶看到的现场记录

系统提示（system）= 该木偶的人设原文 + 它当前的信念、关系、印象（§5.1）+ 一段固定的、**不带任何倾向**的说明：

> 你在一个帐篷里，和另外两位在一起。下面是刚才发生的事。你可以开口，也可以不开口。一次只能有一个在说；如果别人先开口了，你这句就说不出来。

用户消息（user）= 最近 `window` 条现场记录，每条标注相对时间和说话者，例如：

```
(-38s) 新朋友：你们谁最好看？
(-31s) 你（Kaka）：还用问吗（被打断）
(-24s) 新朋友：Charlie 你说呢？
(现在) 没人在说，已经安静 24 秒。你上一次开口是 31 秒前。
```

**只写它们确切知道的事**：谁说了什么、谁被打断在哪、现在谁在说 / 没人在说、安静了多久、（这次开机以来若说过）上一次开口多久前。

**不写的**（2026-09-06 定）：
- 今天第几天、昨晚关过机 —— 那是墙的事。观众感觉漂移靠外面的投影，不靠木偶自己说"我们在这儿六天了"。
- 帐篷里有没有人、新朋友来了 / 走了 —— **除非有可靠来源**（见 §6）。靠人声猜的来去是猜测，不当事实说给它们听。
- 开机后第一轮不写"你还没开过口"—— 那不是真的，它昨天说过。不知道就不提。
- "这句话是在问你""你应该回答""Kaka 已经说太多了"之类的东西 —— 永远不写。

### 4.2 模型的回答格式（2026-09-26 起：两步）

**第一步 · 决定**（所有木偶同时、同样快）：

```json
{ "feeling": "……", "intent": "……", "speak": true|false }
```

`feeling` 是它此刻的感受，`intent` 是它这次想达到什么 —— 两样都是私下的，谁也听不到，进它自己的"念头"层（§5.1）。`speak=true` 就**立刻**去抢锁。没有"等一下"这个选项。

**第二步 · 台词**（只有抢到锁的那只）：

```json
{ "text": "……" }
```

拿着锁写台词，这一两秒别人来抢会失败 —— 它已经开口了，只是话还没到。允许 text 里用括号写动作或停顿，嘴只念括号外的。写不出来就放锁。

**为什么拆两步、为什么去掉等待**：
- 首演（09-05）发现"谁先生成完谁先说"偏向话短的木偶；于是加了 `wait_seconds` 让木偶自己报时机。
- 09-25 实测发现等待成了**惩罚**：报"等一拍"的（Charlie、Lucy）永远输给报 0 的（Kaka），犹豫在这个房间里直接等于出局。Charlie 三分钟一句没说，它在等一个 Kaka 永远不给的空隙。
- 而且一次决定连台词一起生成，Charlie 心里话多、台词长，生成 3 秒；它常常是**已经决定要说、还没写完**，别人就先到了。话多的人跑得慢，又是机制在指挥。
- 拆两步之后，决定只回三个字段，大家一样快；想说就抢，抢到才写。谁先到锁那儿只剩几十毫秒的运气。犹豫的表达从"等一下"变成"这轮不说"。
- 09-26 实测（v2 人设、白纸记忆、三句人话）：Lucy 4 句、Kaka 4 句、Charlie 2 句；Kaka 有三次"想说但没抢到"。上一版同样条件下 Kaka 6 句、Lucy 2 句、Charlie 0 句。

木偶之间能不能互相打断（Charlie 替 Lucy 出头时掐断 Kaka）—— 待作者看过效果再定。

### 4.3 点名

**不做特殊处理。** "Charlie 你说呢"出现在现场记录里，Charlie 自己读得懂，Kaka 也读得懂"这句不是问我的"。它们各自决定。若实测发现被点名的木偶常常抢不到锁（因为另一只也想插嘴），再考虑给点名加优先 —— 那是一次单独的、要作者点头的决定。

### 4.4 模型

两家都接了，`config.toml` 里 `provider = "openai" | "anthropic"` 一键切换（各自要对应的 key）。2026-09-05 首演用的是 OpenAI `gpt-5.5`，`reasoning.effort = low`；Anthropic 那边是 `claude-opus-5`，`thinking: adaptive`，`effort: low`。低效力的理由一样：这是一句话的角色扮演，不是推理题，更快、更便宜、更少"想太多"。人设与信念是稳定前缀，两家都开缓存。`alt` 是对照档，`use_alt = true` 切过去。

## 5. 记忆

### 5.1 每只木偶记什么

`state/<name>.json`：

```json
{
  "beliefs":   ["说得越少，被误解得越少", "……"],          // 至多 belief_capacity 条
  "relations": { "Charlie": "他现在总护着我，我不需要", "Kaka": "……" },
  "impressions": [                                          // 对到访者的印象，只记印象不记原话
    { "session": "2026-09-05T14:22", "text": "有个人说我肤浅" }
  ],
  "unspoken":  [ { "at": "…", "text": "我本来想说……" } ],   // 最近 N 条未说出口的话
  "updated_at": "…"
}
```

**只记印象，不记原话**：这是隐私边界，也是回音室的机制本身 —— 人不记得别人说了什么，只记得自己因此更加确信了什么。原话只存在于 `transcript.jsonl`（作者可读，木偶不读）。

**念头层**（`thoughts`，2026-09-26 加）：每次决定都记一条 —— 感受、想达到什么、说了什么（或没开口）。不管开没开口都记。这是反刍的主要原料：反刍读的是它自己的感受和策略，而不是它表演出来的话。消化进信念后清空。念头和话之间的差距（Kaka 心里"怕他看穿了我需要被选中"，嘴上"我才不是怕呢"）是作者最想让墙上画出来的东西。

**记忆的语言**（2026-09-26 定）：记忆和信念用平实的语言，跟说话的语言分开 —— 人说话可以有风格，记得的是事。反刍的问法要求：每条一句、三十字以内；写断言和事实，不写比喻、修辞、口头禅；说到人，先写他做了什么，再写我怎么觉得；可以写难听的。这些是对**形式**的约束，跟"信念最多六条"同类，不引导内容。之前没有这条时，反刍读的是三只表演出来的话，信念被写成了同一种腔调（"一句没说完的话像小骨头，轻轻疼"），文风的漂移盖住了立场的漂移。改后的样本：`我必须被选为最好看才安心`、`我不想承认自己需要羡慕`、`Kaka逼Lucy回应，我觉得他不体贴`。

**人设 v2**（`charactor_setting/v2/`，config `[persona] dir`）：按"感受 / 想法 / 策略"三段重写，去掉"诗人""艺术家"—— 作者不追求诗意，要的是感受、想法和策略性表达。Lucy 的"用提问代替表态"从诗人的习惯变成害怕的人的策略。原版人设文件保留。

**分层记忆**（讨论中，未实现）：早期记忆（几乎不变；事实不变、意义可变）→ 信念 → 解读 → 念头 → 话。早期记忆谁写、底层重读的频率，待作者定。

### 5.2 反刍（信念更新）

触发时机：每听到 `ruminate_every` 条发言，或一场到访结束时。

做法：给模型人设 + 当前信念/关系/印象 + 最近一个窗口的现场记录（与木偶平时看到的同一份）+ 未说出口的话，问一件事：

> 经过这些，你现在相信什么？你怎么看另外两位？这位来过的人给你留下了什么？

要求结构化输出，返回完整的新 `beliefs` / `relations` / 本场 `impression`。**信念数量上限**是唯一的约束（`belief_capacity`，默认 6）：超了它必须自己决定丢哪条。丢哪条、改哪条、往哪边改，都不引导。

每次反刍的前后差异写进 `state/changes.jsonl`（谁、什么时候、删了什么、写了什么）—— 这就是以后"墙二"的数据源。

**信念只因"有分量的事"而变**（2026-09-28 定，作者的规则）。之前反刍是整张表重写，信念成了最近几分钟的摘要；一度用"一次最多改一条"限速，作者指出那治的是症状 —— 该变的不是次数，是**理由**。现在反刍问的是："有没有哪一件事分量重到让你改一条信念或对某人的看法？"分量重的事只有四种：有人为此付出了代价或承担了风险；有人在压力下仍然做了某件事；同一个人反复一致地做同样的事；发生在你自己身上的事。单纯的说法（夸一句、骂一句、宣称一句）不算。默认是不改。模型交的是**改动列表**（改哪条、改成什么、因为哪件事），代码只采纳带理由的改动，理由连同改动写进 `changes.jsonl`（墙二每一格改动旁边以后能写"因为那天有人……"）。第五条候选"说话的人是自己信得过的"暂未加入 —— 它会让房间更封闭（观众永远是外人），好坏待作者定。

反刍的时机（听够 `ruminate_every` 句、一场到访结束、关机前听够 `bedtime_min_heard` 句）都只是**反思的机会**，不是改信念的时刻；绝大多数反思的结果是"没有什么事分量够，信念不变"。听到的句数存盘，重启不归零。

**出厂信念**（`--seed`）：记忆是白纸时装第一套信念（4–6 条），有作者审定的 `seeds.json` 就用它，没有才从人设生成；写进 `changes.jsonl` 一条 `seed`。**只有信念出厂；关系、印象、念头、计数全空** —— 关系是相处出来的，不出厂（2026-09-28 作者定：一条模型编出来的"初始看法"等于替它们决定了第一印象）。改了人设就 `--reset 谁 --seed`。

### 5.3 未说出口的话

木偶想开口但没抢到锁，那句话记进它自己的 `unspoken`，参与下一次反刍。它没说出口，但它自己记得。这不是引导 —— 那确实是它想过的话。

### 5.4 落盘

- 每次改动：写临时文件 → `os.replace` 原子替换。任何时刻拔电，最多丢最后一句。
- `transcript.jsonl`、`changes.jsonl`、`sessions.jsonl` 只追加。
- 开机时读所有 state 文件；不存在则从人设文件初始化（信念为空，关系用人设里写明的那几句）。
- **天数**：`state/days.json` 记录每个开过机的日历日；开机时若今天不在里面则追加。第 N 天 = 列表长度。夜里关机不动任何东西。
- 早上开机：现场记录窗口为空，只有一条 `woke_up(day)`。木偶知道"关过机、今天第几天"，记忆全在。接不接昨晚的话头是它们的事。

## 6. 一场到访（session）与"有没有人"的来源（presence）

**"有没有人"是一个可插拔的信号源**（`echo/presence.py`，config `[presence] source`）：

- `source = "none"`（默认，现状）：没有可靠来源。下面这套靠人声的猜测在幕后跑，只管两件内部的事 —— 安静的节奏切档、什么时候落一颗星 / 触发反刍。**木偶不被告知**来去。
- 其它来源（压力垫、摄像头、人体感应…，等帐篷定了再选）：来源在人进来 / 出去时调用 `room.presence_changed(True/False)`。这时"新朋友 来了 / 走了"是事实，写进木偶看到的现场；人声不再自动算"来了"，安静也不再算"走了"，硬件说了算。打不打招呼、谁先打，仍然是它们自己的事。
- 选硬件的依据：要能在**人一动不动地听**的时候仍然知道有人 —— 压力垫（坐）、摄像头（站/蹲，且能数人数）可以，红外感应（PIR）不行，它只知道"刚才有东西动过"。

**靠人声猜的规则**（`source = "none"` 时）：

- 第一句 `human_said` → `visitor_arrived`，一场开始。
- 结束靠一口**安静钟**：只在"没有任何人在说"（人没说、木偶也没说）的时候计时，人在听木偶说话时钟是停的。自上一句人声起，安静累计满 `visitor_timeout`（默认 75 秒）→ `visitor_left`，一场结束，触发一次反刍，三只各自产出对这一场的印象，写进 `sessions.jsonl` 一条记录 —— 这就是墙三上的一颗星。（2026-09-06 改：原先只看"多久没人声"，木偶说话的时间也算，Kaka 讲半分钟、三只轮一圈就把一个安静听着的人判走了。）
- 保底：不管中间发生什么，`visitor_hard_timeout`（默认 300 秒）没有人声就算走了 —— 防止三只自聊不停把一个早已离开的人一直"留"在帐篷里。
- 一场之内说多少句都是同一场；隔天再来是新的一场。
- **声纹缝合**（可选，后做）：只在一个滑动窗口内比对"回来的还是不是刚才那个嗓音"，用于把被长静默切开的同一个人缝回同一场，以及识别"这一场里有两个嗓音"（双星）。不跨场、不存储。

## 7. 耳朵与控制台

### 7.1 耳朵（ears）

用 OpenAI Realtime 的转写模式（音频进、文字出，服务端 VAD）：

- 服务端 `speech_started` → 房间 `human_started`
- 转写完成 → 房间 `human_said(text)`

这样打断检测不用自己写。退路：本地 VAD（silero）+ 普通转写接口，对外事件不变。

**自听风险**（2026-09-06 首测证实：Mac 内置麦的回声消除不够，木偶会自己打断自己；回声残渣还会被转写模型脑补成"山圳""孩子"这类幽灵话）。四道防线，按顺序：

1. **播放期闸门**（`PlaybackGate`，主力）：木偶播放期间加 0.5 秒尾巴，先用头一两秒学"漏音"电平，之后只把**明显比漏音响**（`gate_factor` 倍且不低于 `gate_floor`）的麦克风块送去转写，其余送静音。服务端听不见回声就不会报幽灵事件；真人开口比漏音响得多，照样即时打断。漏音估计只用"不响"的块更新，人声不会把门槛抬高。
2. 服务端近场降噪 + VAD 阈值 0.7。
3. 转写少于 `min_chars`（默认 2）个字丢掉。
4. 转写内容与嘴**最近 8 秒**说过的话做相似度比对，像就丢掉；若已经错误打断，把发言权还回去。

`interrupt = "confirm"`（2026-09-25 起为默认）：木偶说话时不凭"有声音"打断，凭流式转写吐出来的字 —— 凑够 `min_chars` 个不像木偶原话的字才打断（约半秒）。响度闸门治不了木偶自己的重音（一声"汪"被转写成"玩"就把 Charlie 掐了），confirm 才治得了。

**根治：音频走浏览器**（`[audio] io = "browser"`，2026-09-25 起默认）。以上四道都是围堵；病根是 PortAudio 抓的原始麦克风流没有声学回声消除（AEC）。浏览器的 WebRTC 音频栈有成熟的 AEC —— 它知道自己在放什么，能从麦克风里减掉。所以监控台页面加了一个「音频：开」：打开后麦克风在浏览器里抓（`getUserMedia({echoCancellation: true})`），木偶的声音也从浏览器放（`StereoPanner` 分左中右）；麦克风帧经 WebSocket 进引擎（`audio_io.BrowserMic`），TTS 的 PCM 经 WebSocket 出去播（`audio_io.BrowserPlayer` 实现 `mouth.Player`）。浏览器模式下响度闸门关闭。`io = "local"` 保留本机麦克风 + pygame 那条路。帐篷里那台 Mac 要开着监控台页面并点开音频 —— 反正监控台本来就要开。

### 7.2 控制台（console）

键盘替身。读 stdin：输入一行并回车 = 先发 `human_started`，紧接着 `human_said(text)`。单独输入 `.` 回车 = 只发 `human_started`（测打断用，之后再输入的一行是 `human_said`）。它二十行，永远留着 —— 测试、调试、展期中不用对着帐篷喊。

引擎不知道也不关心后面接的是耳朵还是控制台。

## 8. 嘴与动作

### 8.1 嘴（mouth）

- 每只一个音色（沿用 `voices_dic`）→ TTS（流式，按句合成，第一句出来就开始放）→ librosa 升调（沿用 `pitch_dic`）→ pygame 分声道（沿用 `channel_dic`：Charlie 左、Kaka 右、Lucy 中）。
- `stop()`：立即停，返回已播出的文字前缀（用于 `puppet_cut`）。
- 开始播放时发 `motors.speaking(name)`，播完或被停时发 `motors.silent(name)`。
- 关闭模式（无音箱）：只打印，按字数估一个时长睡眠，行为对引擎一致。

### 8.2 动作（motors）

沿用现有串口协议：`1/2/3` = Charlie/Kaka/Lucy 开始动，`4/5/6` = 停。三态：

- **说话**：发开始，持续到说完发停。
- **静默**：停。
- **躁动**（想说但没抢到锁）：短促脉冲 —— 开始、短暂停、停，重复几次。是否启用、脉冲节奏由 config 定；机构惯性要实测。这一态是对事实的呈现（它确实想说没说成），不是引导。
- 无硬件：打印。

## 9. 主循环

```
开机 → 读 config、读 state、追加今天到 days → 发 woke_up(day)
启动：房间、耳朵或控制台、三只木偶、嘴、动作、session、沉默计时器
运行，直到 Ctrl-C
退出：mouth.stop()、motors 全停、串口关闭。state 无需特别处理（早就在盘上）。
```

有人 / 无人不是两种模式，只是 `quiet` 事件的间隔不同，以及 session 计时在跑。

## 10. 旋钮（config.toml）

```toml
[model]
puppet = "claude-opus-5"           # 木偶用的模型
puppet_effort = "low"
ruminate = "claude-opus-5"         # 反刍用的模型
alt = "claude-haiku-4-5"           # 对照档，切换开关

[room]
window = 24                        # 木偶看到的现场记录条数
quiet_interval_with_visitor = 8    # 秒
quiet_interval_alone = 120         # 秒 —— 无人时自聊的节奏
visitor_timeout = 75               # 秒 —— 一场到访的静默结束阈值

[memory]
ruminate_every = 12                # 每听到几句反刍一次
belief_capacity = 6
unspoken_keep = 8

[ears]
mode = "console"                   # console | realtime（阶段 2）

[mouth]
mode = "off"                       # off | tts（阶段 3）

[motors]
mode = "off"                       # off | serial（阶段 4）
port = "/dev/cu.usbserial-1130"
baud = 9600
```

（`use_alt = true` 一键切到对照档；躁动脉冲的开关在阶段 4 加。）

漂移速度不是一个旋钮，是这几个的组合：`quiet_interval_alone`（自聊快慢）、`ruminate_every`（反刍频率）、`belief_capacity`（强制取舍的力度）、`visitor_timeout`。一周展从这组默认值起调；3 天展把 `ruminate_every` 调小；30 天展把 `quiet_interval_alone` 调大、`ruminate_every` 调大。

改 config 后下一轮生效，不用重启。

## 11. 错误处理

- 模型调用失败（网络、限流）：这只木偶这一轮视为不开口，记一条日志。不重试到卡住整个房间。
- 转写失败：丢这一句，记日志。
- TTS 失败：这句用关闭模式（打印 + 睡眠）走完，锁照常释放。
- 串口失败：降级为打印，不影响其它一切。
- 磁盘写失败：这是唯一致命的 —— 退出并报错，因为"随时可拔电"的承诺靠它。

## 12. 测试

先写测试再写实现。所有测试不调真模型、不花钱、不需要 key。

- **假模型**：可编排每只木偶每一轮的回答（说 / 不说 / 说什么 / 延迟多久），用它验证锁、打断、未说出口、沉默事件、点名不做特殊处理。
- **假时钟**：验证 `quiet` 间隔、`visitor_timeout`、有人/无人切换。
- **假嘴、假动作**：记录调用顺序，验证"开始说 → 动作开 → 被打断 → 动作停 → 已播前缀正确"。
- **记忆**：原子写、断电后重读一致、天数只增、反刍前后 changes 记录正确、信念上限生效。
- **控制台**：一行输入 → 两个事件的顺序。
- 真模型只在一个手动脚本里跑（`scripts/live.py`），用来看人设的实际表现。
