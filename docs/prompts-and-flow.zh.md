# 回音室提示词与决策流程

运行规范，2026-10-18。提示词正文直接来自程序读取的同一份语言目录。个人历史保留空白。

台词和反刍均使用通过独立订阅授权调用的 `gpt-6-luna`，思考量为 `low`；两种请求均已实测。脑子失败不会切换到收费 API。

## 流程与信息拼接

角色背景＋当前信念＋最近 N 条现场记录 → 程序直接选人 → 选中的角色写台词 → TTS 播放。人类开口优先。选中的角色必须生成至少一句可朗读台词，不再决定是否开口。

不请求模型判断 speak。事件同轮登记可接话角色，单一明确的句首点名（含常用名字别称）优先；否则随机选择，上一位在有其他人时让位。多人点名或无法确定时使用随机规则。当前 turn_window=0，无定时候选等待。非空字符串由 schema 约束；空白、纯标点或只有动作描述会被本地校验判为生成失败，不当作角色选择沉默。失败不生成假台词，等待下一次事件或安静重试。

### 新版每种用途的信息

| 用途 | 角色背景部分 | 本次任务部分 | 输出 |
| --- | --- | --- | --- |
| 程序选人 | 无模型请求 | 事件、点名、上次发言者 | 获选角色 |
| 写台词 | 身份＋个人历史＋策略＋环境＋当前信念 | 获选时的现场快照＋写台词要求 | text |
| 反刍 | 同上 | 自上次成功反刍以来未消化的实际对话＋反刍场景＋反刍要求 | 信念变化、同伴看法、访客印象 |
| 初始化 | 语言目录中审定的初始信念 | 仅为空白信念安装预设，无模型请求 | 初始信念存盘 |
| 配音 | 对应角色的声音要求 | 已生成的台词；音色、移调和声道由配置指定 | 音频 |

短期窗口 N 由 room.window 配置，当前为 24。每条现场记录包含说话者和说出的内容；被打断时只记实际说出的部分，并标记打断。不是只取人类的话。

### 旧版对照 仅用于理解迁移

| 用途 | 角色背景部分 | 本次任务部分 |
| --- | --- | --- |
| 判断要不要开口 | 人设＋当前记忆＋通用规则 | 现场记录 |
| 写台词 | 同上，仍包含通用规则 | 现场记录＋刚才的感受、意图＋台词要求 |
| 反刍 | 同上，仍包含通用规则 | 现场记录＋积累的念头、未说出口的话＋反刍要求 |
| 生成初始信念 | 人设＋通用规则 | 初始信念要求 |

当前停声检测为 600ms；停声后的续说宽限为 1.2 秒，待本轮转写齐全后提交。程序选人及写台词的实际耗时进入调试日志；模型与语音合成耗时仍会波动。

访客在场时，安静重试间隔为 3 秒（独处时仍为 120 秒）。仅在没有角色发言或生成失败后重试；获选者不再有正常选择空台词的出口。安静提醒不会重启进行中的选人或写台词；访客开口取消旧准备。

浏览器 TTS 模式先启动网页，等唯一声音页面确认音频已就绪后才发布开机事件并开始生成台词。声音页面断开后重新就绪，空闲时立即恢复接话，不等待独处的 120 秒安静周期。网页会显示等待声音页面的启动状态。

### 收音确认

角色播放期间开始的收音，至少累积四个非标点字符且不像角色原话，才触发打断并提交访客发言；停、等等、等一下、别说了、stop、wait 是短指令例外。该规则在打断后保留到本轮结束。短碎片不进入对话或记忆；安静时保留原有短回应。这是针对误识别的保守过滤，不能保证消除所有噪音转写。

个人历史：

## 二 每次调用共用的背景

```text
身份：
{identity}

个人历史：
{history}

惯常策略：
{strategy}

环境及其他设定：
{environment}

你目前相信：
{current_beliefs}
```

history 为空时保持空白，不生成历史。当前信念来自角色保存的 beliefs；初始信念不会重复附在背景里。没有所有角色共用的心理规则，也不发送旧版 NEUTRAL。

## 三 程序选人，无模型开口判断

主流程不调用 decide，也不发送目录内兼容保留的 decide 提示词。不生成 speak、feeling 或 intent；只有获选角色收到写台词请求。

## 四 写台词

```text
最近的现场记录：
{recent_events_and_status}

你获得了本次发言权。
根据你的背景、当前信念和现场，写出你现在说出口的话。
程序已选中你发言；这一步只负责写台词，不再决定是否开口。必须给出至少一句简短、自然、符合你自己的可朗读台词。即使想安静，也用一句话表达，不返回空字符串、纯标点或只有动作描述。
只返回符合格式的 JSON：{"text": "实际说出口的话"}。
```

使用选中时的背景和现场快照；人类插话会取消准备。未入选者不生成台词，也不制造“未说出口”的内容。

## 五 反刍

```text
自上次成功反刍以来的实际经历：
{pending_experiences}

本次反刍的场景：{context}

回顾这些经历，完成以下记录。
1. 当前信念：这些经历是否让你形成新的信念，或改变原有信念？是否改变、什么事情对你有分量，由你根据自身背景判断。没有变化就留空，不必为了完成任务而改变。每处变化写明对应的经历和理由。区分亲身经历、别人说的话和自己的推测；不要把别人的说法直接写成已证实的事实。
2. 对另外两位的看法：分别记录这段经历让你怎样看待另外两位。没有形成看法就不写。写明依据，不补写未发生的事情。每次是独立的新记录，不需要重建过去的看法。
3. 访客印象：{impression_ask}
这些是记录，不是说给别人听的台词。用简短、清楚的文字表达。
返回 JSON：changes 数组中，信念修改用 kind="belief"，who 留空，old 为被修改信念原句（新增留空），new 为新信念，because 为经历和理由；同伴看法用 kind="relation"，who 为同伴名字，old 留空，new 为看法，because 为经历依据。没有记录时 changes 留空。impression 为访客印象。
当前信念最多 {capacity} 条；达到上限时修改已有信念，不额外新增。
```

到访结束时 impression_ask：

```text
这是一场到访的结束：记录这次来访者给你的印象，没有形成印象就留空。
```

其他时候 impression_ask：

```text
本次不是到访结束，impression 留空。
```

context：日常回顾 / 一次到访结束 / 关机前整理

capacity 来自 memory.belief_capacity，当前为 6。changes 和 impression 是接口字段名；relation 表示同伴观察记录，不代表下次调用会读取关系。

| 结果 | 保存方式 | 下次请求是否读取 |
| --- | --- | --- |
| 信念变化 | 更新 beliefs 并保存理由日志 | 是 |
| 同伴看法 | companion_observations 按次追加；保留旧 relations 兼容字段 | 否，包括后续反刍 |
| 访客印象 | impressions 按次追加 | 否，包括后续反刍 |

实际对话按角色存入 pending_experiences，重启后继续保留。成功反刍只消费请求快照中的材料，期间新来的对话留下；失败时材料和计数保留。旧的 thoughts、unspoken 保留兼容，但不再生成或传给模型。现有旧记忆没有这些待处理对话时，无法补回当时遗漏的材料。

触发：累计听到 memory.ruminate_every 条，当前 30；访客离开；关机前有待处理记录且计数达到 bedtime_min_heard，当前 8。反刍计数与短期窗口相互独立。

## 六 初始化

无生成提示词。启动时为空白信念写入本语言审定的初始信念。已有信念不覆盖，不自动重置。个人历史始终空白，等作者补充。

## 七 嘴巴的声音提示词

### Charlie

```text
用普通话朗读输入台词。卡通化、甜腻发嗲的女声气质：偏高且圆润，假甜的微笑音，带一点鼻音和故作亲切的娇柔感；像热情过头、爱撒娇又有点控制欲的阿姨。轻柔黏连地起句，关键字夸张上扬，句尾稍稍拖长再收住，讽刺时仍保持甜甜的礼貌。保持清楚和活泼，不要低沉硬朗，不要机械平读。只读输入台词，不添加称呼、笑声或新词。
```

### Lucy

```text
用普通话朗读输入台词。非常纤细、柔和、温温软软的卡通少女声；小巧的共鸣、轻盈的高音、带一丝气息和羞怯的温柔感，像小小声认真对人说话。音量要足够清楚，字尾轻轻落下，停顿自然细小，情绪有细微变化。不要耳语、尖叫、过度奶声或逐字拖慢；不要机械平淡。只读输入台词，不加入括号提示、笑声或新内容。
```

### Kaka

```text
用普通话朗读输入台词。夸张的卡通鸟类男声，中高音区，尖亮、带一点鼻腔共鸣和俏皮的沙哑边缘；避免低沉稳重、播音腔或成熟绅士感。节奏灵巧跳跃，短促弹跳的重音，音高起伏大，句尾偶尔俏皮上扬，带得意又淘气的笑意。清楚说出每个字，声音有弹性，不要一直尖叫。只演绎原台词，不额外添加笑声、口头禅、叫声或新内容。
```

### 调试用量与配音版本

调试页显示本次进程的脑子实际用量回报：输入（含缓存）、输出（含推理）、角色累计及最近请求。不把缓存或推理再次加入总数；缺失字段显示未知。不含耳朵和嘴，不是订阅余额，也不推算费用。刷新不重置，进程重启清零。旧声音配置与目录保存在 backups/2026-10-18-before-cartoon-voices-and-usage。角色身体能力与环境未修改。新版配音使用 nova/+3 半音（Charlie）、echo/+3（Kaka）、shimmer/+2（Lucy，卡通版），分别配合甜腻发嗲、跳脱卡通鸟和纤细温柔的声音要求。

当前三位均选用卡通版。三位均以 mouth.playback_speed=1.15 直接提高播放采样时钟，速度提高 15%、时长缩短约 13%，同时保留约 +2.42 半音的升高；不是保音高的时间拉伸。此项在角色原有移调之后应用，播放时长与打断进度均按新的采样率计算。原版和首版卡通配置、试听音频均保留。

## 使用和维护

中文：`python -m echo --config config.toml`。英文：`python -m echo --config config.en.toml`，使用独立的 state-en 记忆目录。切换语言或修改提示词需重启。英语版的背景、任务、现场状态、反刍和配音要求均为英语；不会翻译旧记忆或现场原话。

所有运行提示词正文统一在根目录 prompts.txt；旧 charactor_setting 作为历史资料，不再由主程序载入。文档修改应同步更新目录和必要代码，再运行 `python -m echo.prompt_docs`。`python -m echo.prompt_docs --check` 和测试检查正文是否同步。

现有中文信念保留，因此新增的 Charlie 和 Kaka 信念不会被强行写入已有记忆。需要采用完整新初始信念时，由作者明确选择重置并备份；仅修改人设不会自动重置记忆。
