# 末尾 trial 分区供 A/B 试验使用，正式运行不会自动使用；trial.questions 只供旧固定问答测试使用。
# 这是运行程序读取的唯一提示词正文文件。修改后保存为 UTF-8，重启程序生效。
# 修改各个 [分区名] 下方的正文，保留分区名。空的 history 分区可以直接写入个人历史。
# identity 身份 / history 个人历史 / strategy 惯常策略 / environment 环境 / initial_beliefs 初始信念。
# initial_beliefs 每行一条，以 - 开头；最多六条。已有运行记忆不会因修改初始信念而直接改写。
# compose 台词任务 / ruminate 反刍任务 / voices 配音 / performance 表演元数据。
# 保留模板中的 {identity} {history} {strategy} {environment} 及反刍中的 {impression_ask} {capacity}。
# zh 为中文版本，en 为英文版本。两者独立编辑。JSON 输出格式仍由代码约束。

[zh.ruminate]
回顾这些经历，完成以下记录。
1. 当前信念：这些经历是否让你形成新的信念，或改变原有信念？是否改变、什么事情对你有分量，由你根据自身背景判断。没有变化就留空，不必为了完成任务而改变。每处变化写明对应的经历和理由。区分亲身经历、别人说的话和自己的推测；不要把别人的说法直接写成已证实的事实。
2. 对另外两位的看法：分别记录这段经历让你怎样看待另外两位。没有形成看法就不写。写明依据，不补写未发生的事情。每次是独立的新记录，不需要重建过去的看法。
3. 访客印象：{impression_ask}
这些是记录，不是说给别人听的台词。用简短、清楚的文字表达。
返回 JSON：changes 数组中，信念修改用 kind="belief"，who 留空，old 为被修改信念原句（新增留空），new 为新信念，because 为经历和理由；同伴看法用 kind="relation"，who 为同伴名字，old 留空，new 为看法，because 为经历依据。没有记录时 changes 留空。impression 为访客印象。
当前信念最多 {capacity} 条；达到上限时修改已有信念，不额外新增。

[zh.voices.Kaka]

[zh.voices.Lucy]
